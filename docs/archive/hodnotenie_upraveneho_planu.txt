2. Kontraktu chýba skutočný fallback
V2.0 má:
{
  "playback_url": "...",
  "requires_proxy": true
}


To nestačí na automatické prepnutie z priameho prehrávania na proxy.

Doplnil by som napríklad:
{
  "type": "video",
  "format": "mp4",
  "playback_url": "https://cdn.example/video.mp4",
  "fallback_url": "/hls_proxy?url=...",
  "requires_proxy": false,
  "expires_at": null
}


Prehrávanie by najskôr skúsilo playback_url. Pri chybe by automaticky použilo fallback_url.

Zároveň by som doplnil podporu dash pre .mpd a viacero kandidátov streamu, keďže náš Split-Screen už DASH pozná.
3. Bezpečnostné riešenie ešte nie je úplné
Sandbox bez allow-same-origin je správny krok. Prehliadač tak izoluje skripty iframe od dát rodičovskej stránky. 

MDN

Ale:
- Odstránil by som allow-popups-to-escape-sandbox. Pre video prehrávač ho nepotrebujeme.
- Sandbox neznamená, že iframe nedokáže odoslať žiadnu požiadavku na Nexus API. Serverové operácie musia mať vlastnú ochranu.
- /embed_proxy by som ideálne oddelil na samostatný pôvod.
- Kontrolu verejných URL treba uplatňovať aj po HTTP presmerovaní. Súčasná ochrana v url_safety.py to sama negarantuje.
Samotný MDN odporúča pri nedôveryhodnom obsahu aj oddelenie pôvodu, pretože sandbox sa nedá považovať za univerzálnu ochranu. 

MDN

4. Plán stále úplne nesedí s priloženým kódom
V ZIP-e som overil:
- search.js obsahuje _resolvePlayable() a streamResult(), ale nie _resolveQuantumPlayback().
- Split-Screen obsahuje resolveStreamUrl(), ale nie resolveViaNexusBackend().
- _resolvePlayable() momentálne odmietne výsledok bez stream_url, aj keby mal platné embed_urls.
Preto treba výslovne uviesť, že nový kontrakt musí podporovať aj výsledky, ktoré majú iba embed prehrávač.

A samozrejme zosúladiť implementačné body s aktuálnym commitom. ZIP môže byť starší než tvoja pracovná verzia.
Čo by som doplnil do testovania
Nestačí overiť iba to, že resolver správne vygeneruje URL. Potrebujeme overiť samotné prehrávanie.
